## Dev Notes

### Architecture Rules (non-negotiable)

- **AD-3 (Data Store):** `demo-data.json` is loaded into Supabase by `/api/demo/seed` POST — never into localStorage directly. Supabase is always authoritative.
- **AD-3 (Demo bypass):** When `NEXT_PUBLIC_DEMO_MODE=true`, API routes use `DEMO_USER_ID` and skip auth checks. The `users` table demo row already exists in `supabase/seed.sql`.
- **Route pattern:** Follow E1-S3's pattern: `isFlagEnabled()` for env parsing (trim+lowercase, handles TRUE/True/1), framework error rethrow, always return 200.

### Carry-Forward from E1-S3 (CRITICAL)

> E1-S3 review identified a fatal bug: **simulated weather feeds the pattern engine**. The mock constants `{temp:31, humidity:82, psi:45, uv:9}` are flat — every fallback day is identical. Since the pattern engine's `TriggerEntry` uses thresholds like `"humidity > 80%"`, a **constant humidity of 82 on all 14 demo days manufactures a 100%-confidence correlation** against any symptom data.

**What this means for E1-S4:** The demo seed data MUST use **realistic, varied weather values per day**. Generate 14 distinct `weather_snapshot` entries that vary naturally — humidity ranging 60–95%, temp 26–33°C, PSI 30–80, UV 0–11. Only 6–8 of the 14 days should have humidity > 82% (matching the shellfish correlation pattern by design, not by accident of constants).

### Idempotency Pattern

The seed route must be callable multiple times with the same result. Use Supabase `upsert()` with `onConflict` targeting the natural key:
- `users`: `onConflict: "id"`
- `user_profiles`: `onConflict: "user_id"`
- `log_entries`: `onConflict: "user_id, logged_at"` (one entry per user per day)

### Demo Data Structure (`data/demo-data.json`)

```json
{
  "user": { /* DbUser shape */ },
  "profile": { /* DbUserProfile shape */ },
  "logs": [ /* LogEntry[] shape — 14 entries */ ]
}
```

Each log entry must include:
- `id`: UUID (generate 14 stable ones — use deterministic UUIDs based on index so they stay the same across re-seeds)
- `user_id`: `"demo-user-001-0000-0000-000000000000"`
- `logged_at`: 14 consecutive ISO dates ending at today - 1 (gives "1 day ago" recency for demo)
- `food`: realistic hawker meals (laksa, chicken rice, nasi lemak, char kway teow, etc.) with matched `dish_id` references to `hawker_dishes`
- `lifestyle`: sleep_hours, stress_level, stress_type — varied per day
- `skincare`: varied product names per day (Cetaphil, CeraVe, etc.)
- `symptoms`: skin/gut/respiratory severity — eczema pattern: skin flares (6-9) on 8 of 14 days, correlated with shellfish + high humidity
- `weather_snapshot`: **14 distinct, realistic snapshots** — NOT flat constants. Source: "mock", `simulated: true`, `simulated_fields: ["temp","humidity","psi","uv"]`
