## Story

**As a** server-side module,
**I want** a `/api/weather` route that fetches Singapore weather from NEA and falls back to mock data,
**so that** the client always receives weather data without browser-exposed API keys and the app works during NEA outages.

## Technical Notes

### NEA Data APIs (public, no key required)

> ⚠️ The paths originally recorded here were wrong for three of the four endpoints and
> were corrected on 2026-08-08 after verification against the live v2 API. The v2 schema
> is **not uniform** — each endpoint nests its readings differently. Every response is
> wrapped in a `{ code, data, errorMsg }` envelope where `code: 0` means success.

- **Temperature:** `https://api-open.data.gov.sg/v2/real-time/api/air-temperature`
  - Batch: `data.readings[0]` → `{ timestamp, data: [{ stationId, value }] }`
  - Value: mean of `data.readings[0].data[*].value` (Celsius, ~16 stations island-wide)
  - There is **no** `data.records` key on this endpoint
- **Relative Humidity:** `https://api-open.data.gov.sg/v2/real-time/api/relative-humidity`
  - Identical shape to air-temperature; mean of `data.readings[0].data[*].value` (percentage)
- **PSI:** `https://api-open.data.gov.sg/v2/real-time/api/psi`
  - Batch: `data.items[0]` → `{ date, timestamp, updatedTimestamp, readings }`
  - Value: mean of `data.items[0].readings.psi_twenty_four_hourly.{south,north,west,central,east}`
  - There is **no** `national` key — v2 exposes the five regions only
- **UV Index:** `https://api-open.data.gov.sg/v2/real-time/api/uv`
  - Batch: `data.records[0]` → `{ date, updatedTimestamp, index: [{ hour, value }] }`
  - Value: the entry with the latest `hour` — array ordering is not contractual
  - Published across daylight hours only (~07:00–19:00 SGT); empty overnight is expected, not a fault

### Architecture Rules
- AD-5: All weather data flows through `/api/weather` — client never calls NEA directly
- The route is the single source of truth for weather; never expose raw NEA responses to client
- 10-min ISR cache (`revalidate: 600`) reduces NEA call frequency
- `WeatherApiResponse` type from `lib/types/database.ts` defines the contract

### Error Handling
- Any NEA failure for a given signal (network error, timeout, bad status, `code != 0`, missing/invalid value, stale reading, out-of-bounds value) → that signal alone falls back to mock and is named in `simulated_fields`
- Route must always return 200 — client components must never receive a weather 500
- Upstream calls carry `AbortSignal.timeout(5000)`; without it a stalled endpoint runs to the platform limit and returns a 504 from outside the handler's `try`
- Log every failure with its endpoint and cause. A silently-null integration is indistinguishable from healthy mock mode — that is precisely how the original wrong-JSON-path bug shipped undetected
- Errors carrying a `digest` are Next.js control-flow signals (dynamic bailout, redirect, notFound) and **must be rethrown**, never reported as an NEA outage

### Downstream Contract
- Consumers running correlation analysis **must exclude** any signal listed in `simulated_fields`. Mock values are constants — `humidity: 82` sits permanently above the `"humidity > 80%"` trigger threshold and would manufacture a 100%-confidence correlation against real symptom data. Carry-forward requirement for **E5-S1** (pattern engine) and **E1-S4** (demo seed data needs realistic varied weather)
- `fetched_at` is the oldest live observation timestamp in the payload, not the time of the request — persist it directly into `WeatherSnapshot.fetched_at`

### Files to Create
- `app/api/weather/route.ts` — main route handler
- `lib/utils/nea.ts` — NEA fetch helpers (pure async functions, easy to test/mock)

### Decisions Needed — RESOLVED 2026-08-08

**Resolutions (all five now fold into the patch list):**

1. **PSI → mean of the 5 regions.** Path becomes `data.items[0].readings.psi_twenty_four_hourly`, averaged across `{south, north, west, central, east}`. Spec Technical Notes must be corrected — `national` does not exist in v2.
2. **Per-signal fallback, AC3 amended.** Fill only the missing signals from mock and keep the live ones. Response contract widens to `source: "live" | "mock" | "partial"` plus `simulated_fields: string[]`. `WeatherApiResponse` and `WeatherSnapshot` both change.
3. **Simulated data excluded from correlation analysis.** The pattern engine must filter out any log whose weather carries simulated values. E1-S3's obligation is to emit `simulated_fields` accurately so downstream *can* filter; the filtering itself is a carry-forward requirement for **E5-S1**. Demo seed data (E1-S4) needs realistic varied weather rather than the flat constants.
4. **`fetched_at` added, AC4 amended.** Upstream reading timestamp for live signals, request time for mock. Enables the staleness check in patch P11.
5. **Temp and humidity averaged across all stations.** Consistent with the PSI decision and stable against array reordering; both signals sourced identically. Drops the false "nearest to central SG" claim from the spec.

**Original decision items, for the record:**

- [x] [Review][Decision] PSI has no `national` value in the v2 API — `data.items[0].readings.psi_twenty_four_hourly` returns only `{south, north, west, central, east}` (verified live: 56/55/59/64/58). The spec's documented path `records[0].readings.psi_twenty_four_hourly.national` cannot be satisfied literally. A region or aggregation must be chosen: max-of-5 (worst-case, defensible for a health app), `central`, or a mean. Both the code and the spec's Technical Notes need correcting.
- [x] [Review][Decision] All-or-nothing gate discards good readings — `fetchAllNeaWeather` returns `null` if any one signal is null (`lib/utils/nea.ts:81`). NEA publishes UV only ~07:00–19:00 SGT, so once the paths are fixed the route still falls back to **full mock every night**, throwing away three valid live readings and reporting UV 9 / 31 °C at 2 a.m. Per-signal fallback would fix it but contradicts AC3, which mandates a whole-payload mock on NEA failure, and `source: "live" | "mock"` cannot express a partial result.
- [x] [Review][Decision] Simulated weather feeds the correlation engine — mock `humidity: 82` is constant on every fallback response, and `TriggerEntry.factor` uses thresholds of exactly the form `"humidity > 80%"` (`lib/types/database.ts:148`). Every mock day scores as a high-humidity trigger day, so the pattern engine can manufacture a 100%-confidence correlation from a hardcoded constant. `simulated: true` exists but nothing currently excludes simulated rows from analysis. Needs a cross-story call with E5-S1.
- [x] [Review][Decision] `WeatherApiResponse` cannot produce a valid `WeatherSnapshot` — `WeatherSnapshot.fetched_at` is required (`lib/types/database.ts:87`) but the API response has no timestamp field. Consumers must fabricate `fetched_at` at receive time, which is wrong by up to the cache TTL and unbounded for the static mock. Adding the field changes the schema AC4 pins.
- [x] [Review][Decision] Station selection is arbitrary — spec Technical Notes claim `[0]` is "nearest station to central SG"; it is simply the first array element (verified: `S109`, Ang Mo Kio Ave 5), and array order is not contractual. Temp and humidity may come from stations kilometres apart while presented as one reading. Pin a station by ID, average across stations, or drop the claim from the spec.

### Patches

- [x] [Review][Patch] Temperature and humidity JSON paths do not exist — real shape is `data.readings[0].data[0].value`, there is no `data.records` key [clearlah/lib/utils/nea.ts:31, :39]
- [x] [Review][Patch] `cache: "no-store"` nullifies the required 10-min cache — forces the segment dynamic and resets `revalidate` to 0; every request issues 4 uncached NEA calls. Fix is what AC6 literally specifies: `next: { revalidate: 600 }` on the fetch [clearlah/lib/utils/nea.ts:17]
- [x] [Review][Patch] No fetch timeout — a stalled NEA endpoint runs to the platform limit and returns a 504, breaking AC5's never-500 guarantee from outside the handler's `try`. Add `signal: AbortSignal.timeout(5000)` [clearlah/lib/utils/nea.ts:15]
- [x] [Review][Patch] No runtime numeric validation — `as T` cast is unchecked, so a non-numeric upstream value yields `NaN` from `Math.round`, which `JSON.stringify` emits as `null` in a field typed `number` [clearlah/lib/utils/nea.ts:20, clearlah/app/api/weather/route.ts:49-52]
- [x] [Review][Patch] Upstream error envelope ignored — every response is `{code, data, errorMsg}` (verified on all four endpoints); only `res.ok` is checked, so an HTTP 200 carrying `code != 0` is treated as success [clearlah/lib/utils/nea.ts:19]
- [x] [Review][Patch] UV `index[0]` assumes newest-first ordering — ordering is not contractual; sort by `hour` descending and take the latest [clearlah/lib/utils/nea.ts:59]
- [x] [Review][Patch] Bare `catch` swallows Next.js `DynamicServerError` — the framework's dynamic-bailout signal is thrown from inside `fetch` and reported as an NEA outage; rethrow framework errors [clearlah/lib/utils/nea.ts:21-23]
- [x] [Review][Patch] No per-signal failure logging — a permanently broken integration is observationally identical to healthy mock mode; log endpoint + status per failed signal instead of one generic warn [clearlah/lib/utils/nea.ts:19, clearlah/app/api/weather/route.ts:44]
- [x] [Review][Patch] `USE_MOCK_WEATHER === "true"` is strict — `TRUE`, `True`, `1`, or a trailing newline from the Vercel env UI silently enables live mode in an environment that intended mock. Normalize with trim + lowercase [clearlah/app/api/weather/route.ts:35]
- [x] [Review][Patch] No plausibility bounds — `0` and sentinel `-999` pass both null guards and ship as `source: "live"`; humidity is never clamped to 0–100 [clearlah/lib/utils/nea.ts:81]
- [x] [Review][Patch] Upstream staleness never checked — every payload carries a timestamp and none is read, so a stale sensor reading is labelled `source: "live"` and attributed to the wrong day. Reject readings older than a documented threshold (60 min suggested) [clearlah/lib/utils/nea.ts:31, :39, :51, :59]
- [x] [Review][Patch] Humidity precision discarded — `Math.round` drops the real `75.2`-style precision the API returns, while temp keeps 1 d.p. with no stated rationale [clearlah/app/api/weather/route.ts:50]
