# Story 5.2: Insights API Route & Data Fetching

Status: ready-for-dev

## Story

As a client page,
I want an API route that computes correlations, caches results, and triggers AI narration,
so that the Insights page loads quickly with fresh, human-readable trigger insights.

## Acceptance Criteria

1. `app/api/insights/correlate/route.ts` handles GET with `userId` query param
2. Fetches all `log_entries` for user, calls `detectCorrelations()`, stores result in `user_profiles.trigger_cache`
3. Returns `{ status, correlations: CorrelationResult[], narrations: string[], lastUpdated: string }`
4. `narrations`: one plain-English string per correlation, generated by POST to `/api/ai/narrate-insights`
5. Cache invalidation: if `trigger_cache.lastUpdated` within last 6 hours AND log count unchanged, return cache without re-running engine
6. Graceful handling of `insufficient_data`: returns `{ status: "insufficient_data", entries_needed: N }` to client
7. Raw log entries NEVER passed to AI; only `CorrelationResult[]` sent for narration

## Tasks / Subtasks

- [ ] Task 1: Create `app/api/insights/correlate/route.ts` (AC: 1, 2, 3, 5, 6)
  - [ ] 1.1 GET handler: read `userId` from query params, validate
  - [ ] 1.2 Fetch all `log_entries` for user from Supabase, ordered by `logged_at DESC`
  - [ ] 1.3 If < 7 entries: return `{ status: "insufficient_data", entries_needed: 7 - count }`
  - [ ] 1.4 Check cache: read `user_profiles.trigger_cache`; if computed within 6h and log count matches → return cached
  - [ ] 1.5 Call `detectCorrelations(entries)` from `lib/pattern-engine.ts`
  - [ ] 1.6 If correlations found: POST to `/api/ai/narrate-insights` with correlations for AI narration
  - [ ] 1.7 Update `user_profiles.trigger_cache` with new results + computed_at timestamp
  - [ ] 1.8 Return `{ status: "ok", correlations, narrations, lastUpdated }`

- [ ] Task 2: Cache invalidation logic (AC: 5)
  - [ ] 2.1 Read `trigger_cache.computed_at` and compare to `Date.now() - 6 * 3600000`
  - [ ] 2.2 Read current log entry count and compare to `trigger_cache.entry_count` (store this in cache)
  - [ ] 2.3 If both conditions met: return cached result immediately (no engine re-run)
  - [ ] 2.4 Always store `entry_count` alongside `computed_at` in trigger_cache

- [ ] Task 3: AI narration delegation (AC: 4, 7)
  - [ ] 3.1 After engine runs: POST to `/api/ai/narrate-insights` with `{ correlations, userConditions }`
  - [ ] 3.2 Pass ONLY CorrelationResult[] (trigger, pillar, confidence, cooccurrence_count) — never raw logs
  - [ ] 3.3 If narrate-insights unavailable: return correlations without narrations (template fallback)
  - [ ] 3.4 Stub narrate-insights route if E5-S3 not yet built

- [ ] Task 4: Update types (AC: 3, 6)
  - [ ] 4.1 Add `InsightsApiResponse` type to `lib/types/database.ts`
  - [ ] 4.2 Update `TriggerCache` type to include `entry_count` field

## Dev Notes

### Dependencies
- **E5-S1**: `lib/pattern-engine.ts` must exist (provides `detectCorrelations()`)

### Architecture Rules
- **AD-4**: Raw logs never passed to AI. Only the structured `CorrelationResult[]` is sent for narration.
- **AD-3**: `trigger_cache` stored in Supabase `user_profiles.trigger_cache` JSONB.
- Cache is a performance optimisation, not a correctness requirement.

### API Route Pattern
Follow `app/api/profile/route.ts` pattern: validate inputs, try/catch, typed responses, `createClient()` for Supabase.
