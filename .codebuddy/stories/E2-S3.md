## Story

**As a** new user,
**I want** to read and acknowledge a medical disclaimer before I can log anything,
**so that** I understand ClearLah is not a diagnostic tool.

## Acceptance Criteria

1. `/onboarding/step/3` shows full disclaimer: "ClearLah helps you track patterns in your symptoms and lifestyle. It is not a medical diagnostic tool. Always consult a qualified healthcare professional for diagnosis and treatment."
2. Checkbox "I understand — ClearLah is a tracking tool, not a doctor" must be ticked to enable "Let's go"
3. Checkbox NOT pre-checked on page load
4. On completion: `user_profiles.disclaimer_acknowledged = true` AND `users.onboarding_complete = true` written to Supabase
5. Direct navigation to `/dashboard` with `onboarding_complete: false` redirects to `/onboarding/step/1`
6. No app route (except `/`) accessible before disclaimer acknowledged

### API Route Update

The profile route must now handle two sequential writes:

```typescript
// 1. Upsert user_profiles
await supabase.from("user_profiles").upsert({ ...disclaimer_acknowledged: true });

// 2. Update users — only when disclaimer_acknowledged is being set to true
await supabase.from("users").update({ onboarding_complete: true }).eq("id", userId);
```

The `users` update uses `.update().eq()` because the users row was created by seed.sql (INSERT only, not upsert-safe for unknown columns).

Fix: check error AND use `.select()` to verify row count, return 500 if update had no effect. [app/api/profile/route.ts:86-94]
- [x] [Patch] **Use `.maybeSingle()` not `.single()` in dashboard guard** — `.single()` throws PostgrestError when 0 rows match, crashing the page with 500 if user row doesn't exist. [app/dashboard/page.tsx:22]
- [x] [Patch] **Dashboard guard should run in demo mode too** — The `if (!demo)` block skips `onboarding_complete` check entirely in demo mode, allowing dashboard access without disclaimer acknowledgement. [app/dashboard/page.tsx:6-8]
- [x] [Patch] **Add step-completion guard to step/3 page** — Direct navigation to `/onboarding/step/3` bypasses steps 1 and 2, producing profiles with no `tracking_for` or `conditions`. The API should validate that `tracking_for` exists in the profile before accepting `disclaimer_acknowledged`. [app/api/profile/route.ts:37, app/onboarding/step/3/page.tsx]
