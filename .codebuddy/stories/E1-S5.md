## Dev Notes

### Architecture Rules (non-negotiable)

- **AD-6 (Deployment):** Vercel hosts the Next.js app. All secrets (`CODEBUDDY_API_KEY`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`) live in Vercel environment variables ONLY. `.env.local` is gitignored — never committed.
- **AD-6 (Build):** The Vercel build uses Next.js default build pipeline. No custom build scripts needed. `next build` runs `tsc --noEmit` internally (via Next.js 14's default TypeScript integration), but we run `tsc --noEmit` separately for CI-level strictness.

### Pre-existing Build Blocker (MUST FIX in E1-S5)

The pre-existing deferred error from E1-S2 blocks any Vercel deployment:

```
lib/supabase/server.ts(47,16): error TS7006: Parameter 'cookiesToSet' implicitly has an 'any' type.
lib/supabase/server.ts(49,37): error TS7031: Binding element 'name' implicitly has an 'any' type.
lib/supabase/server.ts(49,43): error TS7031: Binding element 'value' implicitly has an 'any' type.
lib/supabase/server.ts(49,50): error TS7031: Binding element 'options' implicitly has an 'any' type.
```

**Root cause:** `@supabase/ssr` v0.3.x `createServerClient` callback receives typed arguments but the current code doesn't type the destructured parameters. Fix: add explicit type annotations matching the Supabase SSR library types.

**Fix reference (from E1-S2 review):** The `createServerClient` callback signature is:
```ts
(cookiesToSet: Array<{ name: string; value: string; options: CookieOptions }>) => void
```

Add a `CookieEntry` type or inline the array types. The function should use `await cookies()` (Next.js 15 API — already done, the `createClient` function is `async`).
